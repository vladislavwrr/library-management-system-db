# 📚 Library Management System DB (PostgreSQL)

Реляционная база данных на PostgreSQL, спроектированная для автоматизации рабочих процессов сети библиотек. Проект включает продуманную архитектуру (в том числе паттерн EAV для динамических атрибутов), генерацию мок-данных, ролевую модель доступа, а также встроенную бизнес-логику на базе триггеров и функций PL/pgSQL.

## 🛠 Ключевые возможности

* **Мультибиблиотечная архитектура:** Поддержка сети библиотек, разделенных на залы (читальные, абонементы, хранилища) и физические места хранения (стеллажи, полки).
* **Гибкая система атрибутов (EAV):** Использование паттерна Entity-Attribute-Value для книг и читателей позволяет добавлять специфичные характеристики (например, "Факультет" для студента или "DOI" для научной статьи) без изменения схемы БД.
* **Автоматизация бизнес-логики:** Реализовано 5 триггеров для управления статусами книг, сроками выдачи и инвентарными номерами.
* **Журналирование (Аудит):** Все важные события (выдача, списание, отказ в выдаче) автоматически фиксируются в таблице `trigger_logs`.
* **Ролевая модель:** Разграничение прав доступа между администратором (`lib_admin`) и рядовым библиотекарем (`lib_worker`).
* **Аналитические запросы:** Включен набор из 16 сложных SQL-запросов для формирования отчетов (популярные книги, должники, выработка сотрудников и т.д.).

## 🗄 Структура базы данных

База данных состоит из следующих логических блоков:

1. **Инфраструктура:** `Library` (Библиотеки), `Hall` (Залы), `Storage_Location` (Места хранения), `Employee` (Сотрудники), `Issue_Rule` (Правила выдачи).
2. **Фонд (Книги):** `Book`, `Book_Category`, `Genre`, `Book_Genre`, `Author`, `Book_Author`, `Book_Copy` (Экземпляры), `Book_Status_Journal` (Статусы).
3. **Пользователи (Читатели):** `Reader`, `Reader_Category`.
4. **Динамические атрибуты:** `Book_Attribute`, `Book_Attribute_Value`, `Reader_Category_Attribute`, `Reader_Attribute_Value`.
5. **Операции:** `Loan_Request` (Учет выдачи и возврата литературы).

## ⚙️ Бизнес-логика (PL/pgSQL Триггеры)

В системе реализованы следующие автоматические процессы:

* `generate_inventory_number`: Автоматически генерирует уникальный инвентарный номер формата `LIB-XXX-YYY-ZZZZZ` при добавлении новой копии книги.
* `check_book_availability`: Блокирует выдачу книги, если её текущий статус отличен от "Доступна" (предотвращает выдачу утерянных или уже выданных книг).
* `calculate_due_date`: Автоматически вычисляет срок возврата (`Due_Date`) на основе правил выдачи конкретного зала (`Issue_Rule`).
* `update_book_status`: При выдаче книги меняет её статус на "Выдана", а при возврате (если срок истек/обновлен) — обратно на "Доступна".
* `set_disposal_date`: Автоматически проставляет текущую дату в качестве даты списания, если статус книги меняется на "Непригодна".

## 📊 Аналитика и отчетность

В скрипте представлены готовые SQL-запросы для решения типовых задач:
* Поиск читателей по сложным критериям (учебное заведение, ученая степень).
* Отслеживание должников (просроченная литература).
* Расчет KPI сотрудников (количество обслуженных читателей).
* Топ-10 самых популярных произведений библиотеки.
* Определение местонахождения конкретного экземпляра (вплоть до полки).
